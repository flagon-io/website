The [welcome](/handbook/welcome) page tells you what this handbook is. This page tells you how it actually works: where it lives, who can change it, and what to do when a page is wrong. The short version is that the handbook is the company. If it isn't written here, it isn't really how we work yet, no matter how many times someone said it out loud.

## The handbook is the source of truth

There's no shadow version of Flagon that the handbook only approximates. This is the real thing. How we work, how we decide, how we pay people: it's all here or it isn't real.

That has a sharp consequence. If a process only exists in someone's head, or in a chat thread, or in the way things have "always been done," treat that as a bug. Undocumented process is a defect we haven't fixed yet, not a charming quirk. The fix is to write it down here so the next person doesn't have to reconstruct it by asking around.

<Callout type="note" title="The handbook-first habit">
  When someone asks how something works, the answer is a link, not a paragraph
  in chat. If there's no link to give, that's a signal a page is missing. Write
  the page, then send the link.
</Callout>

## Anyone can change how the company works

This is the part people don't quite believe at first. The handbook lives in [git](https://github.com/flagon-io). Changing how Flagon operates isn't a matter of getting the founder in a good mood; it's a matter of opening a pull request.

You edit the page, you explain why in the description, you open the PR. It gets reviewed and discussed exactly like a code change: someone reads it, asks questions, pushes back, agrees, and it merges. The same process that keeps bad code out keeps bad policy out, and it lets a good idea from anyone become the actual rule without a meeting.

That's the real reason this is worth doing. A handbook you can only read is a poster. A handbook you can send a pull request to is a way for the smallest crew to keep improving the company in public, one honest edit at a time. It's the same instinct as [open by default](/handbook/values): if changing the rules has to happen in the dark, something's off.

## Everything here is in draft

This handbook is perpetually unfinished, and that's the point, not an apology. Some pages are thorough. Some are a heading and two sentences. A few are probably wrong right now in ways we haven't noticed.

We keep low shame about that on purpose. A rough page that exists beats a perfect page that someone is "still drafting" in private and never ships. If you're waiting until a page is flawless to publish it, you'll wait forever, and everyone else stays in the dark meanwhile. Ship the useful version, then improve it. That's the same instinct we bring to the product; see [ship the smallest useful change](/handbook/iteration).

## How to propose an edit

You don't need permission to suggest a change. You need a reason and a pull request.

- **Found something wrong or missing?** Open a PR against the page. Say what you're changing and why in the description. If you're not sure of the exact wording, propose your best guess; that's easier to react to than a vague question.
- **Not ready to write it yourself?** Open an issue on [GitHub](https://github.com/flagon-io), say hi in [Discord](https://discord.gg/dtYQs6rPXN), or email [hey@flagon.io](mailto:hey@flagon.io). Someone will pick it up.
- **Bigger than a wording fix?** If it changes how a decision gets made, read [how decisions get made](/handbook/decisions) first, then propose it the same way. Every real change to Flagon starts as a pull request against this handbook.
